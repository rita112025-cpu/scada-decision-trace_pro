# scada-decision-trace_pro

SCADA 決議—模型—圖紙追蹤器（MVP）。本機優先的工程協調事項台帳：追蹤每項會議決議或文件要求，是否已反映到指定圖紙版次或 BIM 模型，並保留可回查的來源與驗收證據。

- 只用 Python 標準函式庫（`http.server`、`sqlite3`、`csv`），**不需 `pip install`**
- 服務只綁 `127.0.0.1`，不呼叫任何外部 API、雲端 LLM、遙測或 CDN
- 不讀取、不修改、不上傳任何 PDF／DWG／RVT／Excel 原檔；台帳只記錄檔名與路徑文字
- 不需管理員權限，不改登錄檔、PATH、Program Files 或系統服務

## 需求

- Windows 10/11
- Python 3.10 以上（使用者層級安裝即可；開發時以 3.12.10 測試）

## 放置位置（重要）

請放在**短路徑**，例如 `C:\tools\scada-decision-trace`。
路徑超過 260 字元時，Windows 的 `cmd` 與 SQLite 會無法開檔（備份會失敗並顯示提示）。

## 啟動

1. 在檔案總管雙擊 `start.bat`
2. 瀏覽器會自動開啟 `http://127.0.0.1:8765/`
3. 黑色視窗保持開著（關掉就等於停止服務）

第一次用可按右上角「載入範例」看虛構示範資料。

## 停止

擇一：

- 在 `start.bat` 的黑色視窗按 `Ctrl+C`
- 雙擊 `stop.bat`

## 設定操作者名稱與埠號

1. 複製 `config.example.json` 為 `config.json`
2. 修改 `operator`（寫入變更紀錄的操作者名稱）與 `port`
3. 重新啟動

`config.json` 與 `data/` 已列入 `.gitignore`，不會進版控。

### 證據與狀態規則

- 來源檔名、頁碼／段落、原文摘錄任一缺漏時，不能標為「已確認」，系統自動改為「缺乏證據」並提示
- 新增事項未指定時，預設為「待確認」＋「缺乏證據」，不會預設成已確認
- 狀態設為「已驗收」時，驗收結果必須為「通過」且必須填驗收證據路徑
- 逾期＝有期限、期限早於今天、且狀態不是「已驗收」或「已關閉」（當天到期不算逾期）
- 議程草稿只整理既有資料，不新增事項、不推定決議；結論欄留空待會後回填

### 變更紀錄

每次新增、修改、匯入、清除範例，都逐欄記錄：時間、操作者、動作、欄位、修改前值、修改後值。沒有實際變動的儲存不會產生紀錄。

## CSV 匯入／匯出

- 匯出為 **UTF-8 BOM**，中文 Windows Excel 直接雙擊開啟不亂碼
- 匯入接受 UTF-8（含／不含 BOM）與 **cp950**（Excel「另存為 CSV」的預設編碼）
- 欄位標題可用中文（如「標題」）或英文鍵名（如 `title`）；唯一必要欄位是「標題」
- 「事項編號」已存在 → 更新該筆；空白或不存在 → 新增
- **任一列驗證失敗就整批不匯入**，並列出錯誤列號
- 匯入前自動備份
- 期限接受 `2026-03-05` 或 Excel 常見的 `2026/3/5`
- 以 `= + - @` 開頭的儲存格匯出時會加 `'` 前綴，避免 Excel 當公式執行；匯入時自動移除

- 網頁右上角「備份」

## 還原

1. 雙擊 `stop.bat` 停止服務（服務執行中會拒絕還原）
2. 在專案資料夾開命令提示字元，執行：

```bash
python -m sdt restore data\backups\sdt-backup-20261014-213426-216784.db
```

3. 畫面會顯示「還原前已自動備份目前資料：…pre-restore…」與「還原完成」

還原會先驗證檔案是本工具的 SQLite 備份；備份檔以唯讀方式開啟，不會被修改。還原錯了，可再用 `pre-restore` 那份還原回來。

## 逐字稿匯入與文件關聯（第一階段）

這階段把逐字稿收進既有事項台帳：匯入 → 產生決議／待辦草稿 → 人工確認後才入帳 → 從事項頁搜尋 local-notebook 並建立關聯。不接 CAD／Revit，也不修改 Transcript_translation 或 local-notebook。

### 安裝與啟動

需求與原本相同：Python 3.10 以上，只用標準函式庫，不需要 `pip install`。

1. 複製 `config.example.json` 為 `config.json`
2. `local_notebook_url` 指到 **已啟動的** local-notebook 網頁（見下方）。本服務預設埠是 8765，local-notebook 的預設埠也是 8765，請把其中一邊改開，範例把搜尋服務放在 `http://127.0.0.1:8766`
3. `local_notebook_db` 可留空。要「定位來源」時才填 local-notebook 的 `notebook.db` 絕對路徑
4. 啟動本服務：`python -m sdt serve` 或雙擊 `start.bat`

`local_notebook_url` 只允許 `http://127.0.0.1` 或 `http://localhost`。查詢不會送到其他位址，也不會把逐字稿或工程文件上傳到外部服務。

local-notebook 需另依該專案的說明安裝並啟動，例如在它的目錄執行（埠請避開 8765）：

```bash
python -m src.ui
```

它的網頁搜尋是 `GET /api/notebooks` 與 `GET /api/search`。這個介面沒有「依段落編號取回檔案路徑」的 API，所以定位會另以唯讀方式開啟 `local_notebook_db`。資料庫裡的 `sources.original_path` 實際是它複製到 `data/originals` 的路徑，不是你當初選的原始路徑，也不是本台帳的副本。

### 專案 ID

事項原本只有可修改的「專案」文字。現在每個專案有不可變的 `PRJ-` 編號，名稱可以改，編號不跟著改。既有資料庫在下次開啟時會依原來的專案文字補上編號，不刪除事項或變更紀錄。名稱相同的舊資料會歸到同一個編號。

逐字稿、草稿、入帳後的事項，以及文件關聯，都帶這個編號。畫面可以用專案篩選，不同專案的事項和關聯不會混在一起。

### 匯入

網頁按「匯入逐字稿」。先選專案與檔案，按「預覽」，確認專案、檔名、段落數、時間資訊是否齊全，再按「確認匯入」。

實際接受的格式：

| 格式 | 依據 | 時間 |
| --- | --- | --- |
| Transcript_translation JSON 匯出 | 欄位含 `model`、`language`、`source_filename`、`mode`（`cloud`／`local`）、`text`、`raw_text`、`segments`、`duration_seconds`、`status`（必須是 `completed`）、`export_time`。每個 segment 含 `id`、`start`、`end`、`speaker`、`text`、`raw_text`、`edited`、`timestamp_source` | 使用檔內的開始與結束秒數，標為「齊全」 |
| 帶起訖時間的 TXT | 單行 `[HH:MM:SS.sss–HH:MM:SS.sss] 文字`。區間可用 `–`、`—` 或 `-`，兩側可有空白。秒可以是整數或 1～3 位小數，內部記到毫秒 | 有開始與結束才標完整時間。一行一個段落，不要求段間空白行 |
| Transcript_translation TXT 匯出 | 單行 `[HH:MM:SS] 講者：文字` | 只保存開始時間，結束時間留空。不補造結束時間 |
| 混合 TXT | 上面幾種和沒有時間的行可以在同一個檔案。開頭的中文標題列也算沒有時間的段落 | 每行分開判斷。某一行格式錯誤不會把其他行改成無時間。換行接受 LF、CRLF、只有 CR，以及 Unicode 行分隔 |
| 其他 UTF-8 TXT | 沒有時間標記的非空白行 | 以行號定位，時間標為「無時間資訊」 |

預覽會分別列出：完整時間、只有開始時間、沒有時間、時間錯誤的段落數。分秒超界、負時間、小數超過三位、結束早於開始，會標在該行，不補造時間。抽取用的正文會拿掉行首時間標記；存檔的原始行不改。

已經匯入、但當時沒有解析出時間的 TXT，可在「匯入逐字稿」裡選該筆，先預覽再套用重新解析。這會保留逐字稿 ID、原始行、草稿審核狀態、已入帳事項與原始引用，不需要刪資料庫或再匯入一次。對不上的舊段落不會刪。新出現的行只補段落，不自動產生草稿。

不接受 SRT、VTT、其他編碼，或欄位對不上的 JSON。空檔、格式錯誤、非 UTF-8 都會直接說明原因，而且不會寫入半套資料。

系統保存檔案內容雜湊、正規化換行後的全文、原始段落 id（JSON）或行號（TXT），以及檔案裡真正有的時間。換行會先編成 LF 再計算雜湊。同一個專案再次匯入相同內容時會提示，不新增第二份來源，也不再產生草稿。

`examples/synthetic/` 是虛構範例，不是真實會議或工程文件。

### 草稿與入帳

本專案沒有既有的抽取器。這一階段不呼叫付費 API、不上傳逐字稿、也不下載模型，只用可解釋的規則產生候選：

- **明文決議**（規則 D1–D6，`rule:v2`，信心高）：「決議：」「定案」「決定採用／同意採用」「會議通過／審查通過」「予以確認」「本次核准／今天核准」。單獨的「核准」「決定」「確認」，以及「核准過」「已經核准」這類歷史敘述，不會因為出現關鍵字就變成決議。
- **明文待辦**（規則 T1–T3，信心高）：有「待辦」，或同一句是「請＋姓名＋動作」，或「請於／應於某日之前」。
- **口語**（`rule:v4` 的 D7／T4，信心中）：在明文沒對上時，才看常見講法，例如「那就這樣」「就這樣定」「就照這個做」「我們就採用」「確定用」「不用改了」「先維持原案」「OK那就」，以及「回去確認」「要再提供」「下次會議前」「我們這邊會」「再回覆」「補給我們」。句首的「對／嗯／那／就是／然後」可以留著，單獨的「對」「嗯」「好」「OK」不夠。
- 「麻煩」只有後面接著對象和動作（確認、提供、回覆、更新、補）才算待辦。「你們先」也要接著動作。「那就這樣」若這句在談預算、報價、費用，或帶著「但是／不過／可是」，不列為定案。「但是麻煩你多給一點預算」這種議價不是交辦。`rule:v3` 仍可重跑，用來對照較寬的舊結果。
- 口語先排除問句（嗎、呢、要不要、是不是、會不會、？）、假設與提議（如果、可能、應該、建議、要不然、考慮）、否定與取消、以及「核准過」「之前已經」「上次」這類過去的事。「然後就是核准過的版本」仍然不是決議。
- 本機可以在驗收目錄放 `cues.json`（見 `examples/synthetic/cues.example.json`）加自己的說法。這個檔已列入 `.gitignore`。本機驗收會讀它，但終端不印清單；問句和歷史敘述即使含有清單裡的詞也不收。網頁匯入只用內建規則，不會去讀這個檔。清單對上的信心標為低。
- 每筆草稿有「對上的說法」和信心。信心不是模型分數，只表示說法有多明文。
- 同一句若兩種都像，只留一筆決議草稿
- 負責人、期限只有這一句明文寫出才填，否則空白。不依講者或前後文猜人名、日期
- 本句若有「這個、這樣」等指代，會附上前一段的段落 ID、時間與原文供核對，但不會把兩段拼成一句原始引用
- 每筆候選帶規則編號、抽取理由，以及需人工核對的缺漏

這些規則不完整，可能漏掉口語，也可能誤收。畫面上的每一筆草稿都會附上這段限制，**必須人工確認**後才能入帳，不能把規則當成不會誤判。你可以改摘要、負責人、期限；摘要改了，原始引用仍留著。按「確認入帳」才會變成正式事項（決議對應「會議決議」，待辦對應「待辦」）。「捨棄」或尚未確認的草稿不會出現在事項表。同一筆草稿再確認一次不會多一筆事項。

已有逐字稿來源或文件關聯的事項，不能直接改掛到別的專案（API 會拒絕，編輯畫面的專案選單也會停用）。這樣文件關聯才不會留在原專案、從列表消失，卻又因為段落編號重複而無法重新關聯。要歸到其他專案請另建事項。同一專案只改名稱則不受此限，事項的 project_id 維持不變。

入帳後的原文在事項對話框按「回查此段原文」。修改標題或描述不會覆寫原始引用。

### 關聯工程文件

在已存在的事項裡搜尋 notebook、關鍵字，結果只顯示 local-notebook 實際回傳的檔名、摘錄、頁碼或行號或時間戳。選取後建立關聯，不必手打檔名。

關聯的狀態固定是「未主張支持」。它只表示你選了這個出處，不表示文件支持該決議，也不會把整份文件複製進台帳。

建立關聯時，若已設定 `local_notebook_db`，會從該資料庫讀取實際存在的檔名、筆記本名稱與 `sources.file_hash`（local-notebook 匯入時計算的檔案雜湊）當成來源指紋。搜尋 API 本身不回傳雜湊，呼叫端自填的雜湊、版本或章節也不採用。沒設定資料庫時仍可依搜尋結果建立關聯，但沒有內容雜湊，之後不能標成「可定位」。

定位時不能只靠 `source_id` 與 `chunk_id`。指紋（檔名、筆記本、內容雜湊）對不上時，狀態是「無法驗證」，原檔名與其他已保存欄位保持不變，不會改顯示成另一份文件。

- 搜尋服務沒開、連不上，或網址不是本機：事項列表與既有資料照常可用，畫面只顯示連線失敗
- 指紋相符且複製檔還在：定位狀態是「可定位」，並給出 `original_path`
- 指紋相符，但段落已被刪除或複製檔不在該路徑：狀態是「來源失效」，關聯紀錄與原檔名仍留著
- 沒設定資料庫、指紋不符，或建立時沒有內容雜湊：狀態是「無法驗證」

## 已知限制

- 單機單人使用；沒有登入，操作者名稱來自 `config.json`
- 不提供刪除事項（保留稽核軌跡）；不需要的事項請改為「已關閉」
- 不解析 PDF／DWG／RVT 內容；來源與證據以檔名、路徑文字記錄
- 路徑超過 260 字元會無法啟動或備份（見「放置位置」）
- 決議／待辦草稿是字面規則，不是語意模型。否定與取消只涵蓋已列出的句式，其餘仍可能誤收或漏收，入帳前要人工確認

### 整合測試

本台帳執行時只用標準函式庫。`tests/test_notebook_live.py` 會另外啟動真正的 local-notebook，因此需要該專案與下列套件。路徑用環境變數 `SDT_NOTEBOOK_ROOT`（未設定時預設 `/tmp/source-repos/local-notebook`）。套件版本釘在 `requirements-integration.txt`，只給這個測試使用。

一般執行時，若 clone、套件或 SQLite FTS5 trigram 不在，該測試會略過。整合驗收不允許略過：

```bash
pip install -r requirements-integration.txt
SDT_NOTEBOOK_ROOT=/path/to/local-notebook SDT_INTEGRATION_STRICT=1 python -m unittest discover -s tests -v
```

缺少上述環境時，這個模式會失敗，不會顯示 skip。結果要分開看通過、失敗、錯誤、略過；略過不算通過。

### 第二階段本機驗收（Windows）

雲端環境不得讀取真實會議。真實 TXT 與參考用的 `SCADA會議紀錄.docx` 只放在你自己的電腦，預設目錄：

`C:\Users\user\sdt-verify`

原始檔維持唯讀。驗收腳本不覆寫、不搬移、不刪除它們，不連外網，也不會把候選確認入帳。`SCADA會議紀錄.docx` 只是待核對參考，腳本不讀內文、不當成正確答案。報告寫在該目錄的 `reports\`，已被 `.gitignore` 排除。

安裝與啟動台帳（不需要為了日常使用而 pip install）：

```powershell
cd C:\path\to\scada-decision-trace_pro
py -3 -m sdt serve
```

把要檢查的 UTF-8 TXT 放在驗收目錄第一層。對得上逐字稿的項目才寫進 `annotation.json`（欄位見 `examples/synthetic/annotation-template.json`，也可改用 `annotation.csv`）。每一筆答案都要有 `file`、`line`、`sentence`：`sentence` 是該行由 1 起算的句序。只填行號不夠；跨檔案同一行、同一行多句、重複標註，或對不到唯一一句時，整份 precision／recall 會拒絕計算，那些筆不會算成命中。對不到的放 `pending.json`，不進入分母。你自己判定的誤收放 `false-positives.json`。然後：

```powershell
cd C:\path\to\scada-decision-trace_pro
powershell -ExecutionPolicy Bypass -File .\scripts\verify_local.ps1
```

或：

```powershell
py -3 scripts\verify_local.py --dir C:\Users\user\sdt-verify
```

終端只顯示狀態碼與彙總數字（檔案數、段落數、句子數、時間警告數、候選數、決議數、待辦數、標註數、待確認數、誤收數、是否完成評分、拒絕筆數）。段落數若是 0，表示時間列沒有被拆開。完整報告、候選原文、對上的說法、人工備註、檔名與路徑只寫進該目錄的 `reports\verify-report.txt`，不會印到終端。`cues.json` 的清單原文也不印。錯誤同樣只給狀態碼與固定錯誤代碼。

虛構標註算出的 precision／recall 只描述那批合成句子，不是真實會議的準確率。

沒有標註檔時，報告只給候選數、時間分段數，以及你若已填寫的誤收與待確認；不計算 precision／recall，也不聲稱召回率。標註都能唯一定位、且預測與答案可以一對一配對時，才會分別列出決議與待辦的 precision、recall，並寫明分子、分母和樣本是哪些 TXT。配對鍵是種類、檔名、行號與句序。

已匯入的逐字稿可以分開做兩件事：重新解析時間，以及依目前規則重新抽取候選。兩者都先預覽。重新抽取只補上來源位置還沒有的草稿，不覆寫既有摘要、原文、審核狀態或已入帳事項，也不會自動確認入帳。相同句子若出現在不同段落，會各自保留。舊版草稿的原文若還帶著行首時間標記（`–` 或 `-`，小數秒可有可無），會先拿掉標記再依段落與句序對位置，已存的原文不改。對不到唯一位置的舊草稿在預覽與結果裡標成待核對，不會因此新增一筆。抽取版本與新增、略過筆數寫在抽取紀錄。

`examples/synthetic/` 裡的句子是另行編造的，不是從真實會議改寫。
